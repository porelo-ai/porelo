**Why this size.** not estimated.

**What must be true.** Where a host's reading of its organization holds no address for a project it carries, the host's
answer says why: nobody opened the project, or the organization's file for its address stands refused, and by whose key.

Today `porelo org fetch --host` answers `address: null` in both cases and no refusal at all, so nothing on the host can
tell them apart. The host says `the project names no usable central address` and a person is offered a token that cannot
help. Found in the rehearsal of 2026-11-03: a project opened by a key since replaced, on a host set up anew.

The answer's row can carry the reason; showing it needs the host to keep and show a state of its own for a project with
no address, so the two go together. A window asked the same question reads another reader's memory, which may accept what the host refused.
